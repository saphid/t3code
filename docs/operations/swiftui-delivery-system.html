Architecture boundary

Issue state

A lane groups issues; it is not owned by one.

Each issue has one work item. Each work item names one lane. Many work items may name the same lane. Proof and waiting reasons attach to the work item, so unrelated work never creates a global “conflict.”

QueuedIssue, lane, acceptance, rank, dependencies.
→

→
ReproducedRetained base build + image + annotated video.
→
ProvedTests + retained head build + after evidence.
→
Proof-readyEvery capture visually reviewed for intent and side effects.
→
Phone-testOnly an authorized validated generation can install.
→
AcceptedHuman verdict bound to exact phone generation.
→
PR / landedSeparate authority and receipts.

Any head change returns that work item to active and invalidates later proof. It does not block an unrelated issue.

Machine cleanup

Archive first. Delete later, separately.

InventoryOriginal path, Git branch, dirty/untracked state, disk size.
→
Lean ZIPPreserve source + Git state; exclude reproducible caches and build output.
→
Verifyunzip -t, size, SHA-256, manifest.
→
Review windowOriginal directories remain untouched now.
→
Separate approvalOnly then remove superseded originals.

The checkouts are large relative to free disk, so archival is batched. This avoids a half-created archive consuming the remaining space and provides a reviewable inventory before any deletion.

Honest remaining work

What still needs proving.

P0 Disposable end-to-end pilot

Run one real issue from capture through simulator proof, validate a Test generation plan, and stop before physical-phone installation. This exposes ergonomic gaps schemas cannot.

P1 Installed-phone attestation

The protocol validates the previous Test receipt and exact carry set. It does not yet independently ask the phone whether those exact bytes are currently installed.

P1 RocketSim visual acceptance

Record one tap, swipe, and pinch example; visually review type, touch size, trails, trimming, bezels, backgrounds, and captions on both desktop and phone.

P2 Build retention policy

Keep content-addressed builds now. Measure real disk growth, then choose explicit retention limits. Avoid speculative automatic deletion.

P2 Archive removal decision

Verified archives do not authorize deleting originals. Review the manifest and allow a recovery window before a separately approved removal pass.
