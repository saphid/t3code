## Handoff rules / honest limits

1. **The planned slice minimum is narrower than the native RPC surface.** implementation-plan.md:62 names status/refs/diff and stage/unstage/commit/branch/PR operations, but native clients also call pull (#23), worktree add/remove (#15, #16), init (#28) and PR checkout/materialization rides on resolve/prepare (#22). Each needs an explicit fold-into-`t3.source-control/repository` or narrow-new-contract decision before P10 — today they are PLANNED-adjacent, not covered.
2. **Staged state is the biggest read-side data gap (#3).** Native parses porcelain XY and drops it (GitVcsDriverCore.ts:1736–1804); commit file-selection is caller-supplied `filePaths` on the stacked action. A plugin staging lane needs a net-new, narrowly scoped status addition — this is the only row where the native wire cannot serve the panel at all.
