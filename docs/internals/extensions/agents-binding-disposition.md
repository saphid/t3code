## Handoff rules / honest limits

1. **The panel is read-only; every write scenario is a thread-level orchestration command.** Start (#6), cancel (#7), settle (#12) and approval (#8) have no per-agent addressing anywhere in the native client — they run through `orchestration.dispatchCommand` (rpc.ts:1089, operate scope RpcAuthorization.ts:26). A contract that pretends plugins can address individual subagents would exceed native capability; bounded start/cancel/settle/approval under `t3.orchestration/*` (plan row 63) is exactly the native shape.
2. **Checkpoint rows are P12-bound per the controlling instruction (#9, #10, #11).** The transport (`dispatchCommand`) and read RPCs (`getTurnDiff`/`getFullThreadDiff`) already exist and are generic; what is blocked is the public checkpoint semantics (`CheckpointRef`, turn-count ranges, destructive-restore contract). These rows block retirement of the native checkpoint UI only. The `t3.review/diff` family owns the diff payloads themselves.
3. **The roster rides a legacy fold with a v2 escape hatch (#2).** `subagentRuntime.ts` is documented bridge code that a v2 subagent projection replaces outright, never merges (726–738). The contract thread must define the subscribed activity payload so the fold (or its v2 successor) can be package code — including the `agentKind` stamp (#5), linkage fields (#14), and provider-specific usage frames (#4). Losing any of these strands the roster.
4. **Native-absent behaviors must not be faked (#15 workflow launch, #20 log/output inspection, #21 session deep link).** Verified absent in web/desktop UI (runHandles data is carried but unconsumed; no launch call site exists). Any future support is net-new design, not extraction parity.
5. **Two narrow reads sit outside the planned slice minimum (#16, #17, #22).** Workflow-script viewing exists as a contained native RPC but is unnamed in plan row 63; project-script listing and agent-session scan/import are settings/provisioning reads with no public contract at all. Each needs an explicit fold-into-slice or narrow-new-contract decision before P13 — today they are PLANNED-adjacent, not covered.
6. **Script run is the one EXISTING row and it is composite (#18).** The public `t3.terminal/control` contract covers open/write, but the native flow layers busy-terminal allocation, worktree/cwd/env selection and focus requests on top (ChatView.tsx:3205–3290) — those stay panel glue. Capability-gated degradation (#12 settlement gate) and idle-as-nonterminal status semantics (#3) are honesty requirements the contract must preserve, not implementation details.
