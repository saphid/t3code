## Handoff rules / honest limits

1. Three narrowly scoped new contracts are required (`t3.workspace/resources` complete-read, `t3.workspace/search`, remote-open state). Everything else reuses existing or already-planned slices — this is NOT fourteen new APIs, per the parent's C01 ruling.
2. **Full native-size editing (#19) is the explicit deferral / extraction blocker.** Native reads serve 1 MiB (`WorkspaceFileSystem.ts:31`); the text-edits checkpoint is 24000 bytes (`textEdits.ts:14`). Retiring the native editor requires the separately versioned resource-transfer decision — not a silent cap enlargement.
3. **The component-library / react-dom / theme-injection cliff (#18, #21) is real but out of scope of the accepted refinements.** Flagged for a parent UI-kit decision; this table does not resolve it and does not vendor a workaround into a contract.
4. Bounds parity: the resources complete-read contract must carry an explicit truncation state so the plugin mirrors the native 1 MiB + `truncated` behavior exactly.
5. Every PKG-HELPER row keeps behavior in the panel package and talks only to public/planned contracts — no private `~/` application imports in the shipped plugin.
6. Rows #24–#26 are additions over the GLM draft: environment-scoping for resource/preview URLs, the atom/RPC transport plumbing, and the shared-utils import cluster were previously unnamed bindings.
