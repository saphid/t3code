# Browser binding disposition table — pre-extraction handoff (P08-A)

Stage: sdk-refinements-follow-on. Date: 2026-09-12.
Prepared by: Devin swe-2-medium (worker, macbook-pro checkout `t3-extensions-authoring`, branch `devin/p08-browser-skeleton`).
Basis: `docs/internals/extensions/browser-capability-plan.md` (the chosen `t3.browser/sessions` boundary, still unimplemented), verified line-by-line against local source on this branch.
Sibling format: `docs/internals/extensions/files-binding-disposition.md` (F1).

Scope: this table MAPS each native Browser/preview behavior or private binding to a disposition. It is the extraction handoff contract. It does NOT implement the Browser panel and does NOT authorize any code change. An explicitly deferred binding blocks retirement of that native feature.

Terminology: the native feature is the **preview panel** (`PreviewPanel`/`PreviewView`, surfaced as `t3.browser`). The **engine** is the host-owned Chromium `<webview>` (Electron `desktopBridge.preview`). The **session metadata** is the server's in-memory `PreviewManager` (tab records, events, revisions).

## Handoff rules / honest limits

1. **The native engine attachment (#2) is the sole hard extraction blocker and it gates nearly everything.** Unlike Files — where `t3.workspace/files` already existed — no `t3.browser/*` contract exists at all (`catalogue.ts:615-625`). The capability plan's chosen boundary (`t3.browser/sessions` + ResourceRef/lease + declared streams) must land through the parent BEFORE any parity-bearing slice; a server-only metadata adapter is explicitly not an acceptable first replacement (capability-plan.md:73).
2. **The P08-A skeleton is therefore an honest shell, not a browser.** It owns the chrome row + navigation/history view-model + the `t3.file/presentation` descriptor for browser-previewable files (#23 entry), renders the shared `normalizePreviewUrl` behavior, and names the missing engine contract in place of the webview. It claims no navigation write path — none exists publicly.
3. Bounds parity is already specified: URL 2048 / title 512 / tabId 128 / viewport 240–3840 & ≤3840×2160 / zoom ladder / presets incl. legacy ids — reuse `packages/contracts/src/preview.ts` verbatim; do not re-derive.
4. `t3.browser` session scope is **thread**, not project (`browserExtension.tsx:40`) — browser tabs are per-thread natively; the plugin surface must match.
5. Rows #17–#19, #22, #33 share two prerequisites the parent owns: the bounded asset capability (screenshots/recordings, never base64 in API results) and the authenticated-host authority model for automation (no fabricated MCP provider sessions).
6. Every PKG-HELPER row keeps behavior in the panel package and talks only to public/planned contracts — no private `~/` application imports in the shipped plugin.
7. A read-only observer is not a replacement: the deferred rows block native-panel retirement until their named contracts land.
