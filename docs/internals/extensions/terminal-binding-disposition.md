## Handoff rules / honest limits

1. **One narrowly scoped new contract is required for reads: a session list/metadata stream** (#1, folding in #32). `t3.terminal/sessions` currently exposes only per-id `inspect`; a plugin cannot discover the terminal ids of a thread it did not itself open. Everything else read-side already exists (#2–#4).
2. **All write/lifecycle paths are blocked on the planned `t3.terminal/control` slice** (#6–#12). Until it lands, the plugin is a read-only observer — explicitly NOT a replacement; per the acceptance bar a read-only observer is never accepted as full parity.
3. **Bounds parity note (not silent):** the public output read path serves a bounded tail (snapshot 8 192-byte units at the provider chunking; queue cap 256 KiB / 8 events — terminalOutputEventsApi.ts:25-28) while the native client buffer retains 512 KiB (terminalOutput.ts:45) and server history retains 5 000 lines / 8 MiB (Manager.ts:93-94). A parity slice must either widen the public snapshot bound deliberately or record the reduced scrollback as an accepted difference — never claim equality silently.
