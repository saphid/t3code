## Existing implementation and behavior

The current t3.browser package in apps/web/src/extensions/browser/browserExtension.tsx imports the private PreviewPanel and receives its props through useBindings. It is a wrapper, not an independently replaceable engine consumer. PreviewPanel explicitly reports desktop-only support when the native runtime is absent. An independently packaged replacement must own its controls and use public APIs plus a public native engine attachment; importing PreviewPanel, previewBridge or application stores fails this requirement.

## Shared prerequisites with Terminal

Browser and Terminal need the same trusted invocation, resource and stream facilities before domain adapters. Neither a server-created Browser metadata row nor a terminal snapshot alone supplies these facilities.

The broker will construct an immutable HostApiInvocationContext as a host-only argument, never a caller-provided JSON object:

- callId, optional parentCallId, rootCallerId and immediate callerId;
- providerId and providerGeneration;
- rootPrincipal with authenticated session identity, principal kind, and connection identity where the entry transport has a persistent connection;
- callerGenerations containing each plugin identity, immutable content receipt and grant revision;
- resolved scope and cancellation signal.

The exact TypeScript representation must be agreed once with the Terminal design. HTTP entry does not imply a native renderer connection: the engine attachment binds a separately authenticated host connection. Agent and host entry points use their own authenticated principals. ViewContext.client and namespace remain hints/scope, never authority. Root and immediate caller permissions are intersected through the entire chain, including stream continuation and engine commands. This improves host service attribution within the existing trusted-code model; it does not sandbox shared-realm JavaScript or ambient Node access.

A public ResourceRef identifies an environment/project/thread-scoped resource using a host-generated opaque ID. Its owner record binds provider identity and resource epoch. A transient lease binds the resource, resource epoch, provider generation and explicit rights to the authenticated principal and caller chain on the host. A serialized handle alone grants nothing. Stable identity does not transfer opaque state or engine ownership to another selected provider. Installation replacement, revocation and owner failure invalidate affected leases. Browser metadata is currently in-memory: persistence across server restart is a separate migration decision, not implied by stable ResourceRef syntax.

The shared public subscribeApi transport must declare its stream schema and authority, and provide atomic snapshot-plus-live capture, bounded delivery, cancellation and explicit terminal/reset frames. A proposed frame has streamId, sequence, optional resume cursor, type (snapshot, data, reset or closed), and a schema-validated value. Bounded credit acknowledgement identifies the highest consumed sequence and allowed window. Browser state can coalesce with an explicit new snapshot; terminal output cannot silently lose bytes. Cursor epoch mismatch or lost replay produces reset/reacquire, never invented continuity. No polling is required. The existing catalogue invalidation stream is metadata-only and cannot substitute for domain resource streams.

Whether stream declarations require a new package format or an additive negotiated extension remains a shared SDK decision. Do not publish a Browser-specific transport or silently reinterpret format-2 JSON result methods as unbounded streams.

## Chosen Browser contract boundary

Propose catalogue family t3.browser/sessions at version 1, backed by the current PreviewManager and the real authenticated native engine host. This name and the following shapes are planning choices, not advertised provider availability. Shared resource/stream contracts land first; browserApi.ts then adapts domain behavior rather than owning a second engine registry.

| Method or channel  | Input and result                                                                         | Authority and completion                                                                                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| capabilities       | Scoped context to supported operations, engine kinds and availability reasons            | Read. Distinguish native engine available, host disconnected and unsupported client. No fabricated web or mobile engine.                                                         |
| acquire            | Optional URL, viewport and allowed profile reference to resource plus lifecycle snapshot | Write/create. Host derives thread/environment, creates resource and lease, chooses an authorized native host, and reports creating until attachment acknowledgement.             |
| snapshot           | Resource reference plus authorized lease to bounded session state                        | Read. Includes resource epoch, revision, lifecycle, URL/title, navigation availability and advertised controls. Excludes cookies, credentials and arbitrary engine internals.    |
| navigate           | Resource, lease, checked URL to operation receipt                                        | Write/navigation. Resolve current resource and scope, validate URL, dispatch to the bound engine and distinguish accepted from completed/failed.                                 |
| history/reload     | Resource, lease and explicit back/forward/reload/hard-reload operation to receipt        | Action-specific writes. No generic bridge command string. Revalidate capability and generation at dispatch.                                                                      |
| subscribe          | Resource and authorized read lease, optional cursor to declared state/event stream       | Read with continuing authority checks. Atomic snapshot and later changes; closed/reset explains replacement, disconnect or epoch change.                                         |
| close              | Resource and authorized close lease to receipt                                           | Write/close exactly one owned resource. Never expose the private close-without-tab operation that can close all thread tabs.                                                     |
| native attachment  | Resource plus presentation lease through a public SDK client host component              | Host owns the real engine and validates the renderer connection. The package controls presentation geometry and chrome, not native webview construction or arbitrary engine IPC. |
| release attachment | Presentation lease to released acknowledgement                                           | Releases presentation ownership and subscriptions. It does not navigate, terminate or delete the browser session.                                                                |

Use existing bounds from packages/contracts/src/preview.ts: URL 2048 characters, title 512, viewport dimensions 240–3840 and area at most 3840×2160. Reuse packages/shared/src/preview.ts normalization: HTTP/HTTPS only, bare loopback addresses default to HTTP and ordinary bare hosts to HTTPS. URL validation does not confer arbitrary fetch/proxy/network permissions. Profile references must belong to the current environment and allowed principal. Engine readiness is a typed acknowledgement from the authenticated renderer, not a timer or successful metadata mutation.

Keep navigation state free of file/frame payloads. Screenshots, recordings and other large outputs need a separately authorized bounded asset capability with MIME/size metadata and reconnect-safe retrieval; they cannot be base64 blobs in ordinary API results. Element annotations need typed targets and existing composer insertion semantics through a separate public composer capability. External system-browser open is a distinct host/client action with checked URL and client policy. DevTools, storage clearing, recording, native input and clipboard actions each require their own advertised operation and grants. Final grant names and schemas are committed together with the shared catalogue, not inferred from a broad browser write grant.

## Lifetime, cancellation and failure

The resource outlives a visible panel. Presentation release, native attachment loss and explicit session close are separate transitions. Hidden/background automation keeps its own authorized activity lease. Engine disconnect makes relevant operations unavailable and emits a receipt; reconnect requires a fresh authenticated attachment and snapshot. Server restart changes the resource epoch for the existing in-memory backend. Provider selection changes do not replay writes or hand another provider the old native session.

At operation admission and immediately before native dispatch, verify scope, owner, caller/grant generations and required lease rights. Recheck before result delivery. Bind native responses to their request, resource epoch and authenticated connection. A late response from a replaced connection cannot complete the new operation. Cancellation stops queued work and suppresses stale delivery where possible; navigation or storage mutation already performed is not rolled back. Host idempotency must bind principal, resource, operation and bounded request identity, with explicit accepted/completed/failed receipts, rather than trusting plugin call IDs.

## Delivery and parity gates

1. Freeze the current Files checkpoint. Agree Browser and Terminal on trusted context, resource ownership, stream negotiation, assets and client engine attachment. Update the main architecture before implementation.
2. Implement shared facilities with focused tests for spoofed identities, nested attenuation, revoked/replaced generations, multi-client ownership, snapshot/subscription races, backpressure, cancellation and restart.
3. Implement the Browser adapter and public native engine attachment together. Test actual engine acknowledgement, native host disconnect and stale responses. A server-only metadata adapter is not an acceptable first replacement.
4. Build an independent Browser package using only published SDK/contracts. It owns address/history/chrome UI and consumes public services; the host retains native engine construction. Prove the ordinary Browser entry chooses the selected provider and has an explicit path back on disable/unavailability.
5. Complete every inventory row, including profiles, resize/zoom, background tabs, both picture-in-picture modes, captures/recordings, annotations/composer, audio/state, DevTools and storage actions. Retain current built-in behavior until this gate passes; label intermediate navigation-only work as a slice.
6. Parent performs one integrated desktop/native-engine proof with two clients, renderer disconnect/reconnect, provider selection/revocation and server restart. Web, remote/relay, React Native mobile and SwiftUI mobile must report their actual native engine support; no parity claim follows from shared TypeScript compilation alone.

This plan changes documentation only. No Browser provider, renderer adapter or example package is implemented by this step.

## Implemented prerequisite boundary

The current runtime now passes immutable HostApiInvocationMetadata to host API adapters: host call/parent IDs, root/immediate plugin IDs, selected provider lifetime, and each caller installation/content generation. Scope and cancellation remain separate existing arguments. This does not yet carry an authenticated transport principal, bind native connections, allocate resource leases or provide streams. The broader context proposed above is still required before Browser/Terminal ownership can be implemented safely.
