**Same results as base**
- I ported the function to JS exactly and compared it with the base `matchAll` version on 400,000 random strings up to 30 tokens long. The alphabet included `[ ] ( ) < > " '`, space, `\t`, `\n`, non-breaking space and composite tokens like `[a](`, `](`, `(<`. There were 0 mismatches.
- I also worked it through by hand against the pattern `\(\s*(?:<([^>\n]+)>|([^\s)]+))(?:\s+["'][^"']*["'])?\s*\)`:
  - **No hidden backtracking:** at every step, giving up characters would leave a character the next part can't accept. The `\s*` after `(`, the greedy `[^\s)]+` (backtracking leaves a character that is neither whitespace nor `)`), the angle body, and the `\s+` before a title can each only match one way. So the scanner's single forward pass covers every match the regex could find.
  - **Fallback and titles:** when the angle form fails, it falls back to the bare form from the same `<`. `<>` correctly fails the angle form and is taken as the bare href `<>`. A title needs at least one whitespace character first (`end === start` rejects it otherwise), and mixed quote types are accepted, as in base.
  - **Whitespace:** `/\S/`, `/[\s)]/` and `/[>\n]/` use the same JS `\s` definition as the original pattern, so Unicode whitespace is handled the same way.
  - **Shared `]`:** skipping to `labelEnd + 1` when a destination fails is still correct, because every `[` before that `]` ends its label there. Stopping when no `]` is left is also correct.

**Why it's linear**
- `markdownRunEndFinder` (`packages/shared/src/markdownLinks.ts:326`) returns the cached result only when the new start falls inside the stretch it already searched, and nothing in that stretch can match.
- Every finder is called with start positions that only move forward. The loop cursor only increases, and each finder's input comes from that cursor through steps that never go backwards. So searches never overlap and total work is O(n).
- The angle and bare tails have separate caches, so falling back from one to the other can't send a cache back to an earlier position.
- Each regex literal is a new object each time the scanner is built, so nothing shared at module level is left behind.
