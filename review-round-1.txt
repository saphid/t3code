**What I checked against the code**

**Small notes, none blocking**
1. **Untested branch:** no test pushes the legacy fallback (fork PR whose worktree sits on the plain `headBranch` name) past the first page. The fork cases always pre-create `t3code/pr-78/…`. The existing test at `GitManager.test.ts:6466` covers the fallback, but only on a single page. The code path is the same loop, so I'm not counting this as a defect.
2. **Pages can come from different snapshots:** a later page reads whatever snapshot epoch is current at that moment. If another caller refreshes in the middle of the loop, the list could shift and skip an entry. This needs a concurrent refresh while refs are changing, which is very unlikely; the old code had no cross-page issue because it read only one page.
3. **Optional:** passing `limit: 200` (the contract maximum) would halve the number of pages. Each page re-maps and re-sorts the whole snapshot. I wouldn't change it; the query filter already keeps the page count small.
